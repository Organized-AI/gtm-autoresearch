A GTM loop that learns from its own reverts.

GTM Autoresearch already scores a client's container on 12 dimensions, mutates it, and keeps or reverts each change overnight. This box adds the second loop from the Karpathy-loop playbook: it reads every run's ledger, names the habits that keep failing, and proposes a rewrite of how the loop works. The scorer and the rules stay locked, and the owner still publishes.

The stuck target was a scorer rule the loop couldn't satisfy.

After round 5 the only error left in BLADE's container was CE - GA4 Ecom Events: a regex trigger matching view_item_list|select_item|view_cart|add_payment_info, flagged for lacking an EQUALS filter. pickStrategy() always picks the lowest-scoring dimension with an error, and the scores never changed, so it picked trigger quality 24 times. A real fix splits the trigger into 4 EQUALS triggers and re-points 2 tags: 6 entity changes against a budget of 3. Every attempt broke something and was reverted. Meanwhile folder organization (5.2pp of weighted gap), CAPI coverage (4.0pp) and naming (3.9pp) were never touched. Trigger quality was gap #7 of 12.

Exhibit D · AutoLoop's first read

Three habits, and the rewrite it proposes

AutoLoop may change one section of each program.md: "Edit Strategy", the how-to-work part. Constraints, the mutation budget, stop conditions, the weights and evals/ are fixed rules a human owns. The autoloop-scope check applies each proposal to a copy and confirms every other section is byte-identical. Nothing has been written to program.md.

The rewrite won't do anything yet.

parseProgram() in run-gtm-loop.ts reads only the template and snapshot paths. The strategy order and constraints are hardcoded arrays, and pickStrategy() ignores the strategy order anyway. Until the loop reads "Edit Strategy" from program.md, an AutoLoop rewrite, or a human one, changes nothing. That is the first fix in the plan. The second is recording what each reverted round tried, because AutoLoop can only see 2 of its 3 habits without it.

Exhibit E · Using it on an engagement

What the business owner gets, and what you run

The owner gets

  • A staging workspace with the night's best container, a versioned JSON, and a before/after data audit. They publish; the loop never does.
  • A run view link that streams every check and every round, so "did last night's run do anything?" has an answer with a timestamp.
  • Changes to how the loop works arrive as pull requests with the rounds that justify them, never as silent edits.

You run

Exhibit F · Phased plan

Build order, gate by gate

Phase 0this session

Box exists and runs. arb CLI with 22 checks, AutoLoop analyzer, Worker with SSE stream, D1 schema, box.yml CI, and a recorded proof run on the real repo. Branch feat/autoresearch-in-a-box.

Phase 1 · G1lock the scorer

Make the contract real. Add .claude/settings.json denying edits to evals/**. Rewrite parseProgram() to read Constraints, Mutation Budget and Edit Strategy from program.md, and make pickStrategy() follow them. Fix HRE's weights table or add Google Ads to its snapshot so 12 means 12.

Phase 2 · G2a ledger that teaches

Record every attempt. Each round writes strategy, operations, candidate dimensions and the dimensions still failing, reverted or not. Add a stall stop (3 reverts in a row on an unchanged container). Keep manifest.json pointed at the best winner automatically.

Phase 3 · G3AutoLoop live

Proposals as pull requests. arb autoloop --pr opens a PR touching only Edit Strategy, with the evidence rounds in the body. Only the owner merges. Rerun BLADE with the merged habits and compare against 77.3%.

Phase 4 · G4beyond the score

Passing the scorer isn't done. Run a Playwright preview check on each kept round, call jev-site-scan to compare configured tags with what fires, and keep Jev in shadow mode journaling every keep/revert.

Phase 5deploy + distribute

One link per client. Deploy the Worker, point CI at it, and publish the guide under guide.organizedai.vip/gtm-autoresearch/box. Package box/ so a new client folder gets the same gates.

First step: apply the Organized Codebase agent templates to .claude/ before writing code. Then read CLAUDE.md and AGENT-HANDOFF/CURRENT-STATE.md.

Context: box/ is "Autoresearch in a Box", an FDE package that maps the Karpathy loop + AutoLoop onto this repo. The inner loop (scripts/run-gtm-loop.ts) is unchanged. box/ adds `arb check` (22 checks, gates G0-G4), `arb autoloop` (reads loop-results ledgers, finds recurring habits, proposes a rewrite of the "Edit Strategy" section of program.md only), a Worker with D1 + SSE run view, and .github/workflows/box.yml. The recorded proof is box/proof/2026-10-03-gtm-autoresearch.jsonl: 11 pass, 7 fail, 1 manual, 3 not built.

Deploy first:
1. cd box && npx wrangler d1 create autoresearch-in-a-box, put the id in wrangler.jsonc, npx wrangler d1 migrations apply autoresearch-in-a-box --remote
2. npx wrangler secret put ARB_INGEST_TOKEN (openssl rand -hex 24), node site/build.mjs && npx wrangler deploy
3. From the repo root: ARB_URL=<worker url> ARB_INGEST_TOKEN=... node box/cli/arb.mjs check all, then arb autoloop. Confirm /run/ streams both live.
4. cp box/templates/box.yml .github/workflows/box.yml (the GitHub App here could not push workflows), then gh variable set ARB_URL and gh secret set ARB_INGEST_TOKEN on the repo so box.yml streams.

Then work gate by gate. A gate is done only when `node box/cli/arb.mjs check <gate>` passes. Never edit box/checks to make a check pass.
G1  Copy box/templates/claude-settings.json to .claude/settings.json (deny Edit/Write on evals/** and box/checks/**). Rewrite parseProgram() so Constraints, Mutation Budget, Stop Conditions and Edit Strategy come from program.md, and make pickStrategy() honor Edit Strategy. Keep the existing tests green and add one test proving an Edit Strategy change alters the chosen target. Fix HRE: either its program.md table lists the 11 dimensions it is actually scored on, or refresh the snapshot with Google Ads data.
G2  Every RoundResult records strategy, operations, candidateScore, candidateDimensions and failingDimensions, for reverted rounds too. Add a stall stop: 3 consecutive reverts on an unchanged container. Update content/gtm-templates/*/manifest.json "best" automatically when a run beats it (BLADE is stale: 76.8 vs 77.3).
G3  Add `arb autoloop --pr`: writes the proposal to a branch and opens a PR that changes only the Edit Strategy section, with the evidence rounds in the body. Only the owner merges. Then rerun BLADE with the merged habits and report the score against 77.3%.
G4  Per kept round, run a Playwright check in GTM preview mode and pass its result as qa to the Jev shadow judge (today it is qa: { status: "absent" }). Call jev-site-scan to compare configured vs observed tags. Jev stays shadow-only.

Rules: no time estimates anywhere. Never publish a GTM container. Commit after each gate passes and update AGENT-HANDOFF/CURRENT-STATE.md. Push to github.com/Organized-AI/gtm-autoresearch and open a PR against main.
