GTM Container Atlas · build kit

Build your own atlas

Everything in the session runs on tools you can set up yourself: a Cloudflare Worker for the audit page and the daily drift check, a few MCP servers so your agent can reach GTM, sGTM and GA4, and one prompt that has Claude Code or Codex install it all.

Three levels

Level 1

Audit

Import a container export, confirm the website, add the sGTM export or skip, review the findings, shape the report and download PDF and Markdown. Needs nothing but a browser: open the atlas.

Level 2

Watch for drift

Save the audited export as a baseline. A daily cron fetches the published container and lists what changed. Your own copy runs on your free Cloudflare account.

Level 3

Workspace and publish

Your agent turns the accepted fixes into a new GTM workspace, creates a version, and publishes only after you say so. Uses the GTM MCP with your own Google sign-in.

Jev: calibrated suggestions

Jev gives each finding a probability for fix, intended or ask the owner. At 75% or more it is confident; under 40% it leaves the call to a person. Pick one backend:

  • Cloudflare Workers AI. Built into the Worker, no key. The default.
  • OpenRouter. Paste your own key in the atlas; any model OpenRouter serves. Good when you already pay for one model.
  • Local jev-style. A small calibrated model on your laptop, no API at all: uv tool install "jev-style[all] @ git+https://github.com/lawrence3699/jev-style" then jev-style serve, and choose "Local jev-style" in the atlas. Only works when the atlas runs on the same machine.

The prompt

Paste this into Claude Code or Codex in an empty folder. It asks before anything that signs in, spends money or publishes.

You are setting up my own copy of the GTM Container Atlas: a GTM audit page, a daily drift check, and the MCP servers that let you audit and fix GTM for me. Work step by step and tell me what you did after each step. Ask me before any step that signs in, creates a paid resource, or changes a GTM container.

1. Check my tools. Confirm Node 20+ is installed. Tell me which agent you are (Claude Code or Codex); use that client's own command or config file for every MCP server below.

2. Get the code. Clone https://github.com/Organized-AI/gtm-container-atlas into ./gtm-container-atlas and read its README.

3. Cloudflare. Run `npx wrangler login` and wait for me to finish the browser sign-in. Then:
   - create the database: `npx wrangler d1 create gtm-container-atlas`
   - put the returned database_id into wrangler.jsonc, remove any "routes" and "account_id" entries, and keep the AI binding and the cron trigger
   - load the schema: `npx wrangler d1 execute gtm-container-atlas --remote --file=schema.sql`
   - deploy: `npx wrangler deploy`
   - open /api/health and confirm it returns ok, drift and jev as true
   Give me the URL.

4. GTM MCP (Stape). Add the remote MCP server https://gtm-mcp.stape.ai/mcp under the name "gtm". It signs in with Google; tell me when to complete the sign-in. Then list my GTM accounts and containers so I can pick one to audit.

5. Optional servers. Ask me which of these I want, then add only those:
   - Stape MCP at https://mcp.stape.ai/mcp with header "Authorization: " (read the key from the STAPE_API_KEY environment variable; never write it into a file in the repo)
   - Chrome DevTools MCP: `npx -y chrome-devtools-mcp@latest`
   - Google Analytics MCP: `pipx run analytics-mcp` (needs Google Cloud credentials; walk me through `gcloud auth application-default login` with the analytics.readonly scope)

6. First audit. For the container I picked, read its live workspace through the gtm server and save it as an export-format JSON file (exportFormatVersion 2, with containerVersion holding tag, trigger, variable, folder and builtInVariable). If the site has a server container, save that too. Open my atlas URL and tell me to drop the files in.

7. Drift. After I finish the review in the atlas, remind me to click "Watch" so the daily check starts.

8. Level 3, only when I ask. Take the operations I accepted in the atlas (the GTM auto tab exports them), and with the gtm server: create a new workspace named "Atlas fixes ", apply the changes, create a version, and show me the diff. Publish only after I type "publish".

When you finish, summarize: my atlas URL, which MCP servers are connected, and what is left for me to do.

Environment variables

For Claude Code on the web or any agent without a browser for sign-in. Set them in the environment settings, never in the repo.

CLOUDFLARE_API_TOKEN
A token with Workers Scripts edit, D1 edit and Workers AI read. Replaces wrangler login.
CLOUDFLARE_ACCOUNT_ID
From the Cloudflare dashboard sidebar.
STAPE_API_KEY
Optional. Stape account → API.
OPENROUTER_API_KEY
Optional. Only if you use OpenRouter for Jev from the agent.
GOOGLE_PROJECT_ID
Optional. For the Google Analytics MCP.

The GTM MCP signs in through a browser, so on the web connect it from claude.ai Settings → Connectors as a custom connector instead of an environment variable.
