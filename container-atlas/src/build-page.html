GTM Container Atlas · build kit

Build your own atlas

Upload a GTM container export, get an audit back. Everything runs on one Cloudflare Worker: the audit page, the Jev model that suggests a decision for each finding, the daily drift check, and the store that keeps every GTM auto round. Here is how it is built, one step at a time.

  your GTM export (.json)

          ▼
  ┌──────────────── Cloudflare Worker ────────────────┐
  │  Assets   audit page: findings, signal flow,       │
  │           review, PDF + Markdown                   │
  │  AI       Jev on Workers AI ── /api/judge          │
  │  D1       drift baselines · GTM auto rounds        │
  │  Cron     daily check of the published gtm.js      │
  └────────────────────────────────────────────────────┘
          │
          ▼
  audit report  →  drift watch  →  GTM Autoresearch  →  new GTM workspace

Build my own GTM Container Atlas with the Atlas Builder. Start with step 1 and ask me only what you need.

At step 5 you choose where Jev runs: on your own Cloudflare account (Workers AI, billed to you), or on the hosted Jev-gateway run by Organized AI, free for 30 days. You need a Cloudflare account (the free plan works) and Node 20 or newer.

Then: edit a container safely

The Container Editor mod turns the audit's fixes into edits. Say edit my container and a pane asks where the container comes from: a GTM ID (you sign in with Google through the GTM MCP), an exported JSON file, or the sample container. Live edits go to a new workspace, never Default Workspace; file edits go to a -edited.json copy; nothing is published until you type “publish”.

/plugin install container-editor@gtm-autoresearch

Step by step

  1. Run an auditLevel 1

    Export your container in GTM (Admin → Export Container → the live version), drop the file on the atlas, confirm the website, and add the server container export or skip it. You get the findings, a guided review and a PDF and Markdown report. Nothing is uploaded; the audit runs in the page.

  2. Get the code

    git clone -b feat/container-atlas-jev-gtm https://github.com/Organized-AI/gtm-autoresearch.git
cd gtm-autoresearch/container-atlas/worker && npm install

    The page source is in container-atlas/src, the Worker in container-atlas/worker, and the Jev question pack in jev-gtm.

  3. Sign in to Cloudflare and create the database

    npx wrangler login
npx wrangler d1 create gtm-container-atlas
npm run db:init

    Paste the database ID that d1 create prints into wrangler.jsonc before db:init. D1 holds drift baselines, daily checks and GTM auto rounds.

  4. Turn on Jev

    Jev runs inside your Worker on Workers AI, billed to your Cloudflare account. No API key, nothing for the people using your atlas to set up. It is one binding in wrangler.jsonc, already in the template:

    "ai": { "binding": "AI" },
"vars": { "JEV_MODEL": "@cf/meta/llama-3.3-70b-instruct-fp8-fast",
          "AUTO_THRESHOLD": "0.75", "ASK_THRESHOLD": "0.40" }

    No Workers AI? Use the hosted Jev-gateway instead, free for 30 days: get a key with POST https://atlas.organizedai.vip/api/jev/trial (your email), store it with npx wrangler secret put JEV_KEY, remove the ai line and set JEV_URL to https://atlas.organizedai.vip/api/judge. The Atlas Builder does this for you if you pick it.

    When an audit is built, the page sends the findings to /api/judge in batches of eight, three at a time. Jev answers each one with a probability for fix, intended or ask the owner. At 75% or more it is confident and the reviewer can accept all of those in one click; under 40% it leaves the call to a person.

  5. Deploy

    npm run deploy

    Open <your-worker>.workers.dev/api/health; it should show drift, runs and jev as true. To use your own domain, add a routes entry with custom_domain: true and deploy again.

  6. Watch for driftLevel 2

    On the last review step, click Watch. The daily cron fetches the published container and lists what changed since your export. When it drifts, GTM Autoresearch re-scores the new version and proposes the cleanup, one guarded round at a time. The GTM auto tab runs the same loop in the page, and every round, accepted or rejected, is saved to D1.

  7. Let your agent publish the fixesLevel 3

    Connect the GTM MCP below to Claude Code or Codex. Your agent takes the operations you accepted, creates a workspace named "Atlas fixes", creates a version, and publishes only after you say so.

The prompt

Paste this into Claude Code or Codex in an empty folder to have your agent do steps 2 to 7. It asks before anything that signs in, spends money or publishes.

You are setting up my own copy of the GTM Container Atlas: a Cloudflare Worker that audits GTM container exports, suggests a decision for each finding with Jev on Workers AI, checks the published container for drift every day, and stores every GTM auto round. Then you connect the MCP servers that let you fix GTM for me. Work step by step and tell me what you did after each step. Ask me before any step that signs in, creates a paid resource, or changes a GTM container.

1. Check my tools. Confirm Node 20+ is installed. Tell me which agent you are (Claude Code or Codex); use that client's own command or config file for every MCP server below.

2. Get the code. Run `git clone -b feat/container-atlas-jev-gtm https://github.com/Organized-AI/gtm-autoresearch.git` and read container-atlas/README.md and jev-gtm/README.md. Work in container-atlas/worker for the Cloudflare steps and run `npm install` there.

3. Cloudflare. Run `npx wrangler login` and wait for me to finish the browser sign-in. Then:
   - create the database: `npx wrangler d1 create gtm-container-atlas`
   - put the returned database_id into wrangler.jsonc (replace REPLACE_WITH_YOUR_D1_ID)
   - load the schema: `npm run db:init`

4. Jev. Confirm wrangler.jsonc has the "ai" binding and the JEV_MODEL, AUTO_THRESHOLD and ASK_THRESHOLD vars. Explain to me in two sentences that Jev runs on Workers AI on my account and what it costs to run.

5. Deploy: `npm run deploy`. Open /api/health and confirm drift, runs and jev are all true. Give me the URL.

6. GTM MCP (Stape). Add the remote MCP server https://gtm-mcp.stape.ai/mcp under the name "gtm". It signs in with Google; tell me when to complete the sign-in. Then list my GTM accounts and containers so I can pick one to audit.

7. Optional servers. Ask me which of these I want, then add only those:
   - Stape MCP at https://mcp.stape.ai/mcp with header "Authorization: " (read the key from the STAPE_API_KEY environment variable; never write it into a file in the repo)
   - Chrome DevTools MCP: `npx -y chrome-devtools-mcp@latest`
   - Google Analytics MCP: `pipx run analytics-mcp` (needs Google Cloud credentials; walk me through `gcloud auth application-default login` with the analytics.readonly scope)

8. First audit. For the container I picked, read its live workspace through the gtm server and save it as an export-format JSON file (exportFormatVersion 2, with containerVersion holding tag, trigger, variable, folder and builtInVariable). If the site has a server container, save that too. Open my atlas URL and tell me to drop the files in.

9. Drift. After I finish the review in the atlas, remind me to click "Watch" so the daily check starts.

10. Fixes, only when I ask. Take the operations I accepted in the atlas (the GTM auto tab exports them), and with the gtm server: create a new workspace named "Atlas fixes ", apply the changes, create a version, and show me the diff. Publish only after I type "publish".

When you finish, summarize: my atlas URL, which MCP servers are connected, and what is left for me to do.

Environment variables

For Claude Code on the web or any agent without a browser for sign-in. Set them in the environment settings, never in the repo.

CLOUDFLARE_API_TOKEN
A token with Workers Scripts edit, D1 edit and Workers AI read. Replaces wrangler login.
CLOUDFLARE_ACCOUNT_ID
From the Cloudflare dashboard sidebar.
STAPE_API_KEY
Optional. Stape account → API.
GOOGLE_PROJECT_ID
Optional. For the Google Analytics MCP.

The GTM MCP signs in through a browser, so on the web connect it from claude.ai Settings → Connectors as a custom connector instead of an environment variable.
