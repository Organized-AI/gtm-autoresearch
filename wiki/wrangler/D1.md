# D1 (Serverless SQLite)

D1 is Cloudflare's serverless SQL database built on SQLite. It runs at the edge, is replicated globally for read performance, and requires zero infrastructure management. D1 is ideal for structured, relational data in Workers applications.

**Key characteristics:**

- Full SQLite SQL support (joins, indexes, triggers, CTEs, window functions)
- Automatic read replication to edge locations
- Built-in migrations system
- Time Travel for point-in-time recovery (up to 30 days)
- 10 GB max database size (on paid plan)
- Free tier: 5 million rows read/day, 100k rows written/day, 5 GB storage

## Database Management

### Create a Database

```bash
wrangler d1 create <DATABASE_NAME> [OPTIONS]
```

| Flag | Description |
|------|-------------|
| `--location <HINT>` | Location hint: `wnam`, `enam`, `weur`, `eeur`, `apac` |

```bash
# Create a database
wrangler d1 create my-app-db

# Create in Western Europe
wrangler d1 create my-app-db --location weur
```

Output:

```
 Successfully created DB 'my-app-db'

  database_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"

Add the following to your wrangler.jsonc:
  [[d1_databases]]
  binding = "DB"
  database_name = "my-app-db"
  database_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```

### List Databases

```bash
wrangler d1 list
```

```bash
# JSON output for scripting
wrangler d1 list --json
```

### Get Database Info

```bash
wrangler d1 info <DATABASE_NAME>
```

Shows database ID, region, size, number of tables, and replication status.

### Delete a Database

```bash
wrangler d1 delete <DATABASE_NAME>
```

> **Warning:** This permanently deletes the database and all its data. This action is irreversible.

## Executing SQL

### Inline SQL Command

```bash
wrangler d1 execute <DATABASE_NAME> --command "<SQL>" [OPTIONS]
```

| Flag | Description |
|------|-------------|
| `--command <SQL>` | SQL statement to execute |
| `--file <PATH>` | Execute SQL from a file |
| `--remote` | Execute against the remote (production) database |
| `--local` | Execute against the local development database (default) |
| `--json` | Output results as JSON |
| `--batch-size <N>` | Number of statements per batch |

```bash
# Create a table (local by default)
wrangler d1 execute my-app-db \
  --command "CREATE TABLE users (id INTEGER PRIMARY KEY AUTOINCREMENT, name TEXT NOT NULL, email TEXT UNIQUE, created_at TEXT DEFAULT (datetime('now')))"

# Insert data locally
wrangler d1 execute my-app-db \
  --command "INSERT INTO users (name, email) VALUES ('Alice', 'alice@example.com')"

# Query local database
wrangler d1 execute my-app-db \
  --command "SELECT * FROM users"

# Execute against REMOTE (production) database
wrangler d1 execute my-app-db --remote \
  --command "SELECT COUNT(*) as total FROM users"

# Execute from a SQL file against remote
wrangler d1 execute my-app-db --remote --file ./seed-data.sql

# JSON output for scripting
wrangler d1 execute my-app-db --remote \
  --command "SELECT * FROM users LIMIT 10" --json
```

### Local vs Remote

| Mode | Flag | Description |
|------|------|-------------|
| Local | `--local` (default) | Uses a local SQLite file in `.wrangler/state/`. Used by `wrangler dev`. |
| Remote | `--remote` | Executes against the production D1 database on Cloudflare. |

> **Important:** `--local` is the default. Always pass `--remote` when you intend to modify or query the production database.

## Migrations

D1 has a built-in migration system that tracks applied migrations and applies them in order.

### Create a Migration

```bash
wrangler d1 migrations create <DATABASE_NAME> <MIGRATION_NAME>
```

```bash
wrangler d1 migrations create my-app-db create_users_table
```

Output:

```
 Successfully created Migration '0001_create_users_table.sql'

The migration is available for editing at:
  migrations/0001_create_users_table.sql
```

Edit the generated file to add your SQL:

```sql
-- migrations/0001_create_users_table.sql
CREATE TABLE users (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT NOT NULL,
  email TEXT UNIQUE NOT NULL,
  password_hash TEXT NOT NULL,
  role TEXT DEFAULT 'user' CHECK (role IN ('user', 'admin')),
  created_at TEXT DEFAULT (datetime('now')),
  updated_at TEXT DEFAULT (datetime('now'))
);

CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_role ON users(role);
```

### List Migrations

```bash
wrangler d1 migrations list <DATABASE_NAME> [OPTIONS]
```

| Flag | Description |
|------|-------------|
| `--remote` | Check remote database migration status |
| `--local` | Check local database migration status (default) |

```bash
# Check which migrations have been applied locally
wrangler d1 migrations list my-app-db

# Check remote
wrangler d1 migrations list my-app-db --remote
```

Output:

```
┌──────────────────────────────────┬────────────┐
│ Name                             │ Status     │
├──────────────────────────────────┼────────────┤
│ 0001_create_users_table.sql      │ Applied    │
│ 0002_add_posts_table.sql         │ Pending    │
└──────────────────────────────────┴────────────┘
```

### Apply Migrations

```bash
wrangler d1 migrations apply <DATABASE_NAME> [OPTIONS]
```

| Flag | Description |
|------|-------------|
| `--remote` | Apply to remote (production) database |
| `--local` | Apply to local database (default) |
| `--batch-size <N>` | Statements per batch |

```bash
# Apply pending migrations locally
wrangler d1 migrations apply my-app-db

# Apply to production
wrangler d1 migrations apply my-app-db --remote
```

### Migration Directory

By default, migrations live in `./migrations/`. You can customize this in `wrangler.jsonc`:

```jsonc
{
  "d1_databases": [
    {
      "binding": "DB",
      "database_name": "my-app-db",
      "database_id": "xxx",
      "migrations_dir": "db/migrations"
    }
  ]
}
```

## Export

Export the entire database or specific tables to a SQL file.

```bash
wrangler d1 export <DATABASE_NAME> --output <FILE> [OPTIONS]
```

| Flag | Description |
|------|-------------|
| `--output <FILE>` | Output file path |
| `--remote` | Export from remote database |
| `--local` | Export from local database (default) |
| `--table <TABLE>` | Export only a specific table |
| `--no-schema` | Skip schema (export data only) |
| `--no-data` | Skip data (export schema only) |

```bash
# Full export from production
wrangler d1 export my-app-db --remote --output backup.sql

# Schema only
wrangler d1 export my-app-db --remote --output schema.sql --no-data

# Data only for a specific table
wrangler d1 export my-app-db --remote --output users.sql --table users --no-schema
```

## Time Travel

D1 Time Travel lets you restore or query your database at any point in the past (up to 30 days on paid plan, 7 days on free).

### Get Time Travel Info

```bash
wrangler d1 time-travel info <DATABASE_NAME> [OPTIONS]
```

| Flag | Description |
|------|-------------|
| `--timestamp <ISO_8601>` | Get the bookmark at a specific timestamp |

```bash
# Get current bookmark and available range
wrangler d1 time-travel info my-app-db

# Get bookmark for a specific point in time
wrangler d1 time-travel info my-app-db --timestamp "2026-04-24T10:00:00Z"
```

### Restore from Time Travel

```bash
wrangler d1 time-travel restore <DATABASE_NAME> [OPTIONS]
```

| Flag | Description |
|------|-------------|
| `--timestamp <ISO_8601>` | Restore to a specific timestamp |
| `--bookmark <BOOKMARK>` | Restore to a specific bookmark |

```bash
# Restore to a specific timestamp
wrangler d1 time-travel restore my-app-db --timestamp "2026-04-24T10:00:00Z"

# Restore using a bookmark
wrangler d1 time-travel restore my-app-db --bookmark "00000001-00000005.cfbkp"
```

> **Warning:** Restoring overwrites the current database state. Consider exporting a backup first.

## Insights

Query performance analytics for your D1 database.

```bash
wrangler d1 insights <DATABASE_NAME> [OPTIONS]
```

| Flag | Description |
|------|-------------|
| `--sort-type <TYPE>` | Sort by: `sum`, `avg`, `count` |
| `--sort-by <METRIC>` | Metric: `time`, `rows_read`, `rows_written` |
| `--count <N>` | Number of top queries to show |
| `--timePeriod <PERIOD>` | Time period: `1day`, `7day`, `31day` |

```bash
# Top 10 slowest queries by average time
wrangler d1 insights my-app-db --sort-type avg --sort-by time --count 10

# Most executed queries in the last 7 days
wrangler d1 insights my-app-db --sort-type count --sort-by time --timePeriod 7day

# Queries that read the most rows
wrangler d1 insights my-app-db --sort-type sum --sort-by rows_read
```

## Worker Code Usage

### Basic Queries

```typescript
interface Env {
  DB: D1Database;
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);

    // --- SELECT multiple rows ---
    const { results } = await env.DB.prepare(
      "SELECT id, name, email FROM users WHERE role = ? ORDER BY created_at DESC LIMIT ?"
    )
      .bind("admin", 10)
      .all();
    // results: { id: number, name: string, email: string }[]

    // --- SELECT single row ---
    const user = await env.DB.prepare(
      "SELECT * FROM users WHERE id = ?"
    )
      .bind(42)
      .first();
    // user: { id: 42, name: "Alice", ... } | null

    // --- SELECT single value ---
    const count = await env.DB.prepare(
      "SELECT COUNT(*) as total FROM users"
    )
      .first("total");
    // count: number

    // --- INSERT ---
    const insertResult = await env.DB.prepare(
      "INSERT INTO users (name, email, password_hash) VALUES (?, ?, ?)"
    )
      .bind("Bob", "bob@example.com", "hashed_pw")
      .run();
    // insertResult.meta.last_row_id -> the new row ID
    // insertResult.meta.changes -> 1
    // insertResult.success -> true

    // --- UPDATE ---
    const updateResult = await env.DB.prepare(
      "UPDATE users SET name = ?, updated_at = datetime('now') WHERE id = ?"
    )
      .bind("Robert", 42)
      .run();

    // --- DELETE ---
    const deleteResult = await env.DB.prepare(
      "DELETE FROM users WHERE id = ?"
    )
      .bind(42)
      .run();

    // --- RAW (returns raw column arrays, more efficient for large results) ---
    const raw = await env.DB.prepare("SELECT id, name FROM users")
      .raw();
    // raw: [[1, "Alice"], [2, "Bob"], ...]

    return Response.json({ results });
  },
};
```

### Batch Operations (Transactions)

```typescript
// Execute multiple statements in a single round trip (transactional)
const batchResults = await env.DB.batch([
  env.DB.prepare("INSERT INTO orders (user_id, total) VALUES (?, ?)").bind(1, 99.99),
  env.DB.prepare("UPDATE users SET order_count = order_count + 1 WHERE id = ?").bind(1),
  env.DB.prepare("INSERT INTO audit_log (action, user_id) VALUES (?, ?)").bind("order_created", 1),
]);

// batchResults is an array of D1Result objects, one per statement
// If any statement fails, the entire batch is rolled back
```

### Exec (Multiple Statements)

```typescript
// Execute raw SQL with multiple statements (no parameter binding)
// Useful for schema setup and seeding
const execResult = await env.DB.exec(`
  CREATE TABLE IF NOT EXISTS settings (
    key TEXT PRIMARY KEY,
    value TEXT
  );
  INSERT OR REPLACE INTO settings (key, value) VALUES ('version', '2.0');
`);
```

## End-to-End Example

Setting up a D1 database from scratch with migrations for a blog application.

### Step 1: Create the Database

```bash
wrangler d1 create blog-db
```

### Step 2: Add Binding to wrangler.jsonc

```jsonc
{
  "name": "blog-worker",
  "main": "src/index.ts",
  "d1_databases": [
    {
      "binding": "DB",
      "database_name": "blog-db",
      "database_id": "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
    }
  ]
}
```

### Step 3: Create Migrations

```bash
wrangler d1 migrations create blog-db initial_schema
```

Edit `migrations/0001_initial_schema.sql`:

```sql
-- Create authors table
CREATE TABLE authors (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  username TEXT UNIQUE NOT NULL,
  display_name TEXT NOT NULL,
  bio TEXT,
  created_at TEXT DEFAULT (datetime('now'))
);

-- Create posts table
CREATE TABLE posts (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  author_id INTEGER NOT NULL REFERENCES authors(id),
  title TEXT NOT NULL,
  slug TEXT UNIQUE NOT NULL,
  content TEXT NOT NULL,
  status TEXT DEFAULT 'draft' CHECK (status IN ('draft', 'published', 'archived')),
  published_at TEXT,
  created_at TEXT DEFAULT (datetime('now')),
  updated_at TEXT DEFAULT (datetime('now'))
);

-- Create tags table
CREATE TABLE tags (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  name TEXT UNIQUE NOT NULL
);

-- Many-to-many: posts <-> tags
CREATE TABLE post_tags (
  post_id INTEGER NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  tag_id INTEGER NOT NULL REFERENCES tags(id) ON DELETE CASCADE,
  PRIMARY KEY (post_id, tag_id)
);

-- Indexes
CREATE INDEX idx_posts_slug ON posts(slug);
CREATE INDEX idx_posts_status ON posts(status);
CREATE INDEX idx_posts_author ON posts(author_id);
CREATE INDEX idx_posts_published ON posts(published_at);
```

### Step 4: Apply Migrations

```bash
# Apply locally first
wrangler d1 migrations apply blog-db

# Verify
wrangler d1 execute blog-db --command "SELECT name FROM sqlite_master WHERE type='table'"

# Apply to production
wrangler d1 migrations apply blog-db --remote
```

### Step 5: Seed Data

```bash
wrangler d1 execute blog-db --remote --command "
  INSERT INTO authors (username, display_name, bio) 
  VALUES ('alice', 'Alice Johnson', 'Tech writer and developer');
"
```

### Step 6: Create a Second Migration

```bash
wrangler d1 migrations create blog-db add_comments
```

Edit `migrations/0002_add_comments.sql`:

```sql
CREATE TABLE comments (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  post_id INTEGER NOT NULL REFERENCES posts(id) ON DELETE CASCADE,
  author_name TEXT NOT NULL,
  content TEXT NOT NULL,
  approved INTEGER DEFAULT 0,
  created_at TEXT DEFAULT (datetime('now'))
);

CREATE INDEX idx_comments_post ON comments(post_id);
CREATE INDEX idx_comments_approved ON comments(approved);
```

```bash
wrangler d1 migrations apply blog-db --remote
```

### Step 7: Worker Code

```typescript
interface Env {
  DB: D1Database;
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);

    // GET /posts -- list published posts
    if (request.method === "GET" && url.pathname === "/posts") {
      const { results } = await env.DB.prepare(`
        SELECT p.id, p.title, p.slug, p.published_at, a.display_name as author
        FROM posts p
        JOIN authors a ON p.author_id = a.id
        WHERE p.status = 'published'
        ORDER BY p.published_at DESC
        LIMIT 20
      `).all();

      return Response.json(results);
    }

    // GET /posts/:slug -- single post with tags and comments
    if (request.method === "GET" && url.pathname.startsWith("/posts/")) {
      const slug = url.pathname.split("/")[2];

      const post = await env.DB.prepare(`
        SELECT p.*, a.display_name as author, a.bio as author_bio
        FROM posts p
        JOIN authors a ON p.author_id = a.id
        WHERE p.slug = ? AND p.status = 'published'
      `).bind(slug).first();

      if (!post) return new Response("Not found", { status: 404 });

      const { results: tags } = await env.DB.prepare(`
        SELECT t.name FROM tags t
        JOIN post_tags pt ON t.id = pt.tag_id
        WHERE pt.post_id = ?
      `).bind(post.id).all();

      const { results: comments } = await env.DB.prepare(`
        SELECT author_name, content, created_at FROM comments
        WHERE post_id = ? AND approved = 1
        ORDER BY created_at DESC
      `).bind(post.id).all();

      return Response.json({ ...post, tags, comments });
    }

    // POST /posts/:slug/comments -- add a comment
    if (request.method === "POST" && url.pathname.endsWith("/comments")) {
      const slug = url.pathname.split("/")[2];
      const body = await request.json() as { author_name: string; content: string };

      const post = await env.DB.prepare(
        "SELECT id FROM posts WHERE slug = ?"
      ).bind(slug).first();

      if (!post) return new Response("Post not found", { status: 404 });

      await env.DB.prepare(
        "INSERT INTO comments (post_id, author_name, content) VALUES (?, ?, ?)"
      ).bind(post.id, body.author_name, body.content).run();

      return Response.json({ success: true }, { status: 201 });
    }

    return new Response("Not found", { status: 404 });
  },
};
```

## Tips and Gotchas

1. **Local is the default.** Running `d1 execute` without `--remote` writes to a local SQLite file. This is intentional for safety but is a common source of confusion.

2. **Migrations are sequential.** Files are sorted lexicographically. The numbered prefix (`0001_`, `0002_`) ensures correct ordering.

3. **Batch is transactional.** `env.DB.batch([...])` executes all statements atomically. If any fails, all are rolled back. Use this for operations that must succeed together.

4. **No ALTER TABLE DROP COLUMN.** SQLite does not support dropping columns. To restructure a table, create a new table, copy data, drop the old table, and rename.

5. **Max 10 GB per database.** For larger datasets, shard across multiple D1 databases or consider a dedicated database provider with [[Hyperdrive]].

6. **Read replicas are automatic.** D1 replicates reads to edge locations. Write performance depends on the primary location.

7. **Time Travel bookmarks.** Every write creates a bookmark. You can recover from accidental data deletion within the retention window. Export a backup before major schema changes for extra safety.

8. **Parameter binding.** Always use `?` placeholders and `.bind()` to prevent SQL injection. Never concatenate user input into SQL strings.

9. **`first()` returns null** for no results. `all()` returns `{ results: [] }` for no results.

10. **D1 is SQLite.** It supports most SQLite features including JSON functions (`json_extract`, `json_each`), full-text search (FTS5), and common table expressions. Refer to the SQLite documentation for available functions.

11. **Foreign keys** are enabled by default in D1. Use `ON DELETE CASCADE` to automatically clean up related records.

12. **Insights** help identify slow queries and optimization opportunities. Check them regularly, especially after adding new queries to your Worker.
