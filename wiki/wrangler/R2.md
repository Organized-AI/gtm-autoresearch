# R2 (Object Storage)

Cloudflare R2 is an S3-compatible object storage service with **zero egress fees**. It stores arbitrary binary data (images, videos, backups, logs, static assets) and is accessible via the S3 API, Workers bindings, or the Wrangler CLI.

**Key characteristics:**

- S3-compatible API (works with existing S3 SDKs and tools)
- Zero egress fees -- read data as much as you want
- Objects up to 5 TB each
- Storage classes: Standard and Infrequent Access
- Built-in data catalog (Apache Iceberg) for analytics
- Sippy for incremental migration from AWS S3 or GCS

## Bucket Management

### Create a Bucket

```bash
wrangler r2 bucket create <NAME> [OPTIONS]
```

| Flag | Description |
|------|-------------|
| `--location <HINT>` | Location hint (e.g., `wnam`, `enam`, `weur`, `eeur`, `apac`) |
| `--storage-class <CLASS>` | Default storage class (`Standard` or `InfrequentAccess`) |
| `--jurisdiction <JURISDICTION>` | Jurisdiction restriction (e.g., `eu`) |

```bash
# Basic bucket
wrangler r2 bucket create my-assets

# With location hint (Western North America)
wrangler r2 bucket create my-assets --location wnam

# EU-only jurisdiction
wrangler r2 bucket create eu-data --jurisdiction eu

# Default to Infrequent Access storage class
wrangler r2 bucket create archive-bucket --storage-class InfrequentAccess
```

### List Buckets

```bash
wrangler r2 bucket list
```

### Get Bucket Info

```bash
wrangler r2 bucket info <BUCKET_NAME>
```

Shows creation date, location, storage class, and other metadata.

### Delete a Bucket

```bash
wrangler r2 bucket delete <BUCKET_NAME>
```

> **Warning:** The bucket must be empty before deletion. Delete all objects first.

## Object Operations

### Put an Object

```bash
wrangler r2 object put <BUCKET/KEY> [OPTIONS]
```

| Flag | Description |
|------|-------------|
| `--file <PATH>` | Path to the local file to upload |
| `--pipe` | Read from stdin |
| `--content-type <TYPE>` | MIME type of the object |
| `--content-disposition <VALUE>` | Content-Disposition header |
| `--content-encoding <VALUE>` | Content-Encoding header |
| `--content-language <VALUE>` | Content-Language header |
| `--cache-control <VALUE>` | Cache-Control header |
| `--expires <DATE>` | Expires header (RFC 2822 or ISO 8601) |
| `--storage-class <CLASS>` | Storage class for this object |

```bash
# Upload a file
wrangler r2 object put my-assets/images/logo.png --file ./logo.png \
  --content-type "image/png" \
  --cache-control "public, max-age=31536000"

# Upload from stdin
echo "Hello R2" | wrangler r2 object put my-assets/hello.txt --pipe \
  --content-type "text/plain"

# Upload to Infrequent Access
wrangler r2 object put archive-bucket/backup-2026-04.sql.gz \
  --file ./backup.sql.gz \
  --storage-class InfrequentAccess
```

### Get an Object

```bash
wrangler r2 object get <BUCKET/KEY> [OPTIONS]
```

| Flag | Description |
|------|-------------|
| `--file <PATH>` | Save to a local file |
| `--pipe` | Write to stdout |

```bash
# Download to file
wrangler r2 object get my-assets/images/logo.png --file ./downloaded-logo.png

# Pipe to stdout
wrangler r2 object get my-assets/hello.txt --pipe
```

### Delete an Object

```bash
wrangler r2 object delete <BUCKET/KEY>
```

```bash
wrangler r2 object delete my-assets/images/old-logo.png
```

## Storage Classes

R2 supports two storage classes:

| Class | Use Case | Storage Cost | Operation Cost |
|-------|----------|-------------|----------------|
| `Standard` | Frequently accessed data | Higher | Lower |
| `InfrequentAccess` | Rarely accessed data, backups | Lower | Higher |

### Update Default Storage Class

```bash
wrangler r2 bucket update storage-class <BUCKET_NAME> <CLASS>
```

```bash
wrangler r2 bucket update storage-class archive-bucket InfrequentAccess
```

## Sippy Migration

Sippy enables **incremental migration** from AWS S3 or Google Cloud Storage. When an object is requested from R2 but not found, Sippy transparently fetches it from the source bucket, serves it, and stores a copy in R2 for future requests. Over time, your R2 bucket fills up with only the objects actually accessed.

### Enable Sippy

```bash
wrangler r2 bucket sippy enable <BUCKET_NAME> [OPTIONS]
```

**For AWS S3:**

| Flag | Description |
|------|-------------|
| `--provider aws` | Source provider |
| `--bucket <NAME>` | Source S3 bucket name |
| `--region <REGION>` | Source bucket region |
| `--access-key-id <KEY>` | AWS access key |
| `--secret-access-key <SECRET>` | AWS secret key |
| `--r2-access-key-id <KEY>` | R2 access key (for verification) |
| `--r2-secret-access-key <SECRET>` | R2 secret key (for verification) |

```bash
wrangler r2 bucket sippy enable my-assets \
  --provider aws \
  --bucket my-s3-bucket \
  --region us-east-1 \
  --access-key-id AKIA... \
  --secret-access-key wJalr... \
  --r2-access-key-id R2KEY... \
  --r2-secret-access-key R2SECRET...
```

**For Google Cloud Storage:**

```bash
wrangler r2 bucket sippy enable my-assets \
  --provider gcs \
  --bucket my-gcs-bucket \
  --client-email sa@project.iam.gserviceaccount.com \
  --private-key "$(cat gcs-key.pem)" \
  --r2-access-key-id R2KEY... \
  --r2-secret-access-key R2SECRET...
```

### Get Sippy Status

```bash
wrangler r2 bucket sippy get <BUCKET_NAME>
```

### Disable Sippy

```bash
wrangler r2 bucket sippy disable <BUCKET_NAME>
```

## Data Catalog (Iceberg)

R2's data catalog enables **Apache Iceberg** integration, allowing you to query R2 data using SQL analytics engines (Spark, Trino, DuckDB, etc.).

### Enable Catalog

```bash
wrangler r2 bucket catalog enable <BUCKET_NAME>
```

### Get Catalog Status

```bash
wrangler r2 bucket catalog get <BUCKET_NAME>
```

### Disable Catalog

```bash
wrangler r2 bucket catalog disable <BUCKET_NAME>
```

### Query with R2 SQL

Once the catalog is enabled, you can run SQL queries against your data:

```bash
wrangler r2 sql query --bucket <BUCKET_NAME> --query "<SQL>"
```

```bash
# Count objects by extension
wrangler r2 sql query --bucket my-assets \
  --query "SELECT extension, COUNT(*) as cnt FROM objects GROUP BY extension ORDER BY cnt DESC"

# Find large objects
wrangler r2 sql query --bucket my-assets \
  --query "SELECT key, size FROM objects WHERE size > 1000000 ORDER BY size DESC LIMIT 20"
```

## Event Notifications

Event notifications trigger when objects are created, deleted, or modified. Notifications are sent to a Queue (see [[Queues]]).

### Create a Notification Rule

```bash
wrangler r2 bucket notification create <BUCKET_NAME> [OPTIONS]
```

| Flag | Description |
|------|-------------|
| `--queue <QUEUE_NAME>` | Target queue for notifications |
| `--event-type <TYPE>` | Event type: `object-create`, `object-delete`, or `object-*` |
| `--prefix <PREFIX>` | Filter by key prefix |
| `--suffix <SUFFIX>` | Filter by key suffix |

```bash
# Notify on all new uploads
wrangler r2 bucket notification create my-assets \
  --queue image-processing \
  --event-type object-create

# Notify only for new images in a specific folder
wrangler r2 bucket notification create my-assets \
  --queue image-processing \
  --event-type object-create \
  --prefix "uploads/" \
  --suffix ".jpg"
```

### List Notification Rules

```bash
wrangler r2 bucket notification list <BUCKET_NAME>
```

### Delete a Notification Rule

```bash
wrangler r2 bucket notification delete <BUCKET_NAME> --rule-id <RULE_ID>
```

## Lifecycle Rules

Automatically transition or delete objects based on age.

### Add a Lifecycle Rule

```bash
wrangler r2 bucket lifecycle add <BUCKET_NAME> [OPTIONS]
```

| Flag | Description |
|------|-------------|
| `--prefix <PREFIX>` | Apply rule to objects matching this prefix |
| `--expire-days <DAYS>` | Delete objects after N days |
| `--transition-to <CLASS>` | Transition to storage class |
| `--transition-days <DAYS>` | Days before transition |
| `--abort-multipart-days <DAYS>` | Abort incomplete multipart uploads after N days |

```bash
# Delete temp files after 7 days
wrangler r2 bucket lifecycle add my-assets \
  --prefix "tmp/" \
  --expire-days 7

# Move old logs to Infrequent Access after 30 days, delete after 365
wrangler r2 bucket lifecycle add my-assets \
  --prefix "logs/" \
  --transition-to InfrequentAccess \
  --transition-days 30

wrangler r2 bucket lifecycle add my-assets \
  --prefix "logs/" \
  --expire-days 365

# Clean up incomplete multipart uploads after 1 day
wrangler r2 bucket lifecycle add my-assets \
  --abort-multipart-days 1
```

### Remove a Lifecycle Rule

```bash
wrangler r2 bucket lifecycle remove <BUCKET_NAME> --rule-id <RULE_ID>
```

### Set All Lifecycle Rules (Replace)

```bash
wrangler r2 bucket lifecycle set <BUCKET_NAME> --file <RULES_JSON>
```

```json
// lifecycle-rules.json
[
  {
    "prefix": "tmp/",
    "expiration": { "days": 7 }
  },
  {
    "prefix": "logs/",
    "transition": {
      "storageClass": "InfrequentAccess",
      "days": 30
    }
  }
]
```

```bash
wrangler r2 bucket lifecycle set my-assets --file lifecycle-rules.json
```

## Object Lock

Object lock prevents objects from being deleted or overwritten for a retention period (compliance / legal holds).

### Add an Object Lock Rule

```bash
wrangler r2 bucket lock add <BUCKET_NAME> [OPTIONS]
```

| Flag | Description |
|------|-------------|
| `--mode <MODE>` | Lock mode: `compliance` or `governance` |
| `--duration <DURATION>` | Retention duration (e.g., `30d`, `1y`) |

```bash
# Compliance lock for 1 year
wrangler r2 bucket lock add audit-logs --mode compliance --duration 1y

# Governance lock for 90 days
wrangler r2 bucket lock add backups --mode governance --duration 90d
```

### Remove an Object Lock Rule

```bash
wrangler r2 bucket lock remove <BUCKET_NAME> --rule-id <RULE_ID>
```

> **Note:** Compliance mode locks cannot be removed or shortened once set.

## Worker Code Usage

```typescript
interface Env {
  MY_BUCKET: R2Bucket;
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);
    const key = url.pathname.slice(1); // remove leading /

    switch (request.method) {
      case "GET": {
        const object = await env.MY_BUCKET.get(key);
        if (!object) {
          return new Response("Not found", { status: 404 });
        }

        const headers = new Headers();
        object.writeHttpMetadata(headers);
        headers.set("etag", object.httpEtag);
        headers.set("cache-control", "public, max-age=31536000");

        return new Response(object.body, { headers });
      }

      case "PUT": {
        const body = await request.arrayBuffer();
        const object = await env.MY_BUCKET.put(key, body, {
          httpMetadata: {
            contentType: request.headers.get("content-type") || "application/octet-stream",
          },
          customMetadata: {
            uploadedBy: request.headers.get("X-User-ID") || "anonymous",
            uploadedAt: new Date().toISOString(),
          },
        });

        return Response.json({
          key: object.key,
          size: object.size,
          etag: object.etag,
        }, { status: 201 });
      }

      case "DELETE": {
        await env.MY_BUCKET.delete(key);
        return new Response(null, { status: 204 });
      }

      case "HEAD": {
        const head = await env.MY_BUCKET.head(key);
        if (!head) {
          return new Response(null, { status: 404 });
        }
        const headers = new Headers();
        head.writeHttpMetadata(headers);
        headers.set("content-length", head.size.toString());
        return new Response(null, { status: 200, headers });
      }

      default:
        return new Response("Method not allowed", { status: 405 });
    }
  },
};
```

## Practical Examples

### Image Upload and Serve API

```typescript
export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url);

    // POST /upload -- upload an image
    if (request.method === "POST" && url.pathname === "/upload") {
      const formData = await request.formData();
      const file = formData.get("file") as File | null;
      if (!file) return new Response("No file", { status: 400 });

      const key = `uploads/${Date.now()}-${file.name}`;
      await env.MY_BUCKET.put(key, file.stream(), {
        httpMetadata: { contentType: file.type },
      });

      return Response.json({ url: `${url.origin}/files/${key}` }, { status: 201 });
    }

    // GET /files/* -- serve a file
    if (request.method === "GET" && url.pathname.startsWith("/files/")) {
      const key = url.pathname.replace("/files/", "");
      const object = await env.MY_BUCKET.get(key);
      if (!object) return new Response("Not found", { status: 404 });

      const headers = new Headers();
      object.writeHttpMetadata(headers);
      headers.set("cache-control", "public, max-age=86400");
      return new Response(object.body, { headers });
    }

    return new Response("Not found", { status: 404 });
  },
};
```

### Backup Script via CLI

```bash
#!/bin/bash
# Daily database backup to R2

TIMESTAMP=$(date +%Y-%m-%d_%H-%M-%S)
BACKUP_FILE="/tmp/db-backup-${TIMESTAMP}.sql.gz"

# Dump and compress
pg_dump mydb | gzip > "$BACKUP_FILE"

# Upload to R2
wrangler r2 object put backups/db/${TIMESTAMP}.sql.gz \
  --file "$BACKUP_FILE" \
  --content-type "application/gzip" \
  --storage-class InfrequentAccess

# Clean up local file
rm "$BACKUP_FILE"

echo "Backup uploaded: backups/db/${TIMESTAMP}.sql.gz"
```

## Tips and Gotchas

1. **Zero egress fees** is the main advantage over S3. If you serve lots of data to users, R2 can save significant costs.

2. **S3 compatibility.** You can use `aws s3` CLI, boto3, or any S3 SDK by pointing to R2's S3 endpoint: `https://<ACCOUNT_ID>.r2.cloudflarestorage.com`.

3. **Multipart uploads** are required for objects larger than ~100 MB. Each part must be at least 5 MB (except the last).

4. **Empty buckets before deleting.** You cannot delete a bucket that contains objects.

5. **Custom domains** require the domain to be on Cloudflare DNS. The `*.r2.dev` dev URL is rate-limited and should not be used in production.

6. **Event notifications** deliver to [[Queues]]. Create the queue first, then set up the notification rule.

7. **Lifecycle rules** are evaluated once per day. Do not rely on them for time-sensitive deletions.

8. **Object lock** in compliance mode is irreversible. Test with governance mode first.

9. **Conditional operations.** The Worker API supports `onlyIf` conditions (etag match, modified since) for cache-efficient serving.

10. **Jurisdiction restrictions** (`eu`) ensure data never leaves the specified jurisdiction. This cannot be changed after bucket creation.
